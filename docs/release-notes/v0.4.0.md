# v0.4.0

## Overview

A webmail release that makes the mailbox simpler to use. The reader's toolbar keeps the everyday actions in view (Reply, Delete, a star and Spam) and moves the rest into a ⋮ menu. Spam and Block sender become one flow: Spam in the reader files the message, and its note offers to block the sender. The header gets a ⋮ menu for Blocked senders, Download a copy and Admin, so the folder bar keeps to Inbox, Sent, Spam and Trash. The selected folder is marked in bold with a bar, in a new brand role `action-text`. The backend, its Candid API and the relay bridge are unchanged.

## Highlights

- **A simpler reader toolbar.**
  - In the Inbox: Reply, Delete, a star, Spam, and a ⋮ "More actions" menu with Mark unread, which closes the message.
  - In Trash and Spam: Reply, the folder's own actions, the star, and in Spam a ⋮ menu with Block sender.
  - At phone width the Back button is an arrow and the actions fit on one row.
- **Spam, then block.** In the Inbox, the reader's Spam moves the message to Spam at once. Its note offers Undo and, once the sender's address is known, Block sender, without a confirmation dialog. The Inbox reader no longer has a Block sender button of its own: blocking a sender from the Inbox now also files the message in Spam. Spam from the list, on ticked messages or a row, offers Undo only.
  - A block's note offers an Undo that brings the message back and unblocks the address. An address that was blocked already stays blocked; the Undo still brings the message back.
  - A block that fails says so, says the message is in Spam, and offers the move's Undo.
  - Block sender and Mark unread wait until the message has loaded: its sender known, and its own mark as read made, so that the mark cannot land after Mark unread.
- **⋮ menus.** A menu closes when an item is chosen, on a click elsewhere (in the message too), when the focus leaves it, when the window's width changes, and on Escape. Choosing an item gives the focus back to the ⋮. The list opens toward the middle of the screen, so it stays on screen.
- **The header's ⋮ "More" menu,** beside Sign out, holds Blocked senders, Download a copy, and Admin for a controller. The folder bar keeps Inbox, Sent, Spam and Trash.
- **The selected folder** is bold, with a bar in the brand's `action-text` colour: beside it, and under the tab at phone width. The mailbox row keeps its tint only.
- **Download a copy** shows its progress below the folders. It ends at sign-out, and when the person no longer has any mailbox; switching mailboxes does not end it.
- **Tests:** browser tests for each change and for every review fix.

## Candid API changes

None. The backend's `email-canister.did` and the relay bridge are unchanged.

## Upgrade notes

**Only the webmail changes.** Deploy the v0.4.0 webmail; do not redeploy the backend or the bridge. This holds for a deployment whose backend runs v0.3.0. One still on v0.2.0 first upgrades its backend as v0.3.0's upgrade notes say, since the v0.4.0 webmail calls the methods v0.3.0 added.

1. Pin v0.4.0 in the deployment repository.
2. Rebuild the webmail with the deployment's brand. A brand that leaves `action-text` out gets its `action`. Where the brand script warns about `action-text` contrast, set `action-text` to a colour that reads on `surface-raised` and `selected` (see "Webmail and settings changes").
3. Deploy the webmail. The release's unbranded `dist` hash is `87a7982deab8ca8257142fa0cd28481784bbb3148c4c136257a3e33a651209df`; the branded output the brand script writes differs from it, as its settings and `brand.css` are the deployment's own.
4. Run the deployment's checks. The backend keeps running v0.3.0's wasm, `05ff9ac7c22e1eacff68f5d3b40fff8316f3e10969889dda51df16e9b69401ca`, which is also v0.4.0's: the build is byte for byte the same. Users reload any webmail tab left open from before the deploy.

**Rolling back** means deploying the v0.3.0 webmail again. Its brand script refuses the `action-text` role, so a brand that sets it must drop it first.

## Webmail and settings changes

- **A new brand role, `action-text`:** the colour of links in mail and of the selected folder's bar. A brand that leaves it out gets its `action` value. The brand script checks it at 4.5:1 on `surface-raised` and 3:1 on `selected`.
- **Links in plain mail** use `action-text` instead of `action`.
- **A role set to `null`** is refused, with a message to leave it out instead.
- The reader's toolbar, the ⋮ menus and the header menu, as above. "Report spam" is now "Spam", in the reader and in the list's toolbar, and the reader's Flag and Unflag button is now a star, as in the list. The Inbox reader's Block sender, with its confirmation, is gone: Block sender comes from Spam's note, and from the ⋮ menu in the Spam folder. Blocked senders, Download a copy and Admin moved from the folder bar into the header menu; their routes are unchanged.
- The `brand.mjs` options are unchanged.

## Known issues

- Mark unread in the list's toolbar or a row's hover action, on the message that is open, can race the reader's own mark as read, so the message can end up read. The reader's ⋮ Mark unread waits for it.
- A Block sender whose reply is lost after the canister stored it shows as failed. The Blocked senders page shows the address.
- At phone width, the device's back gesture leaves the webmail rather than returning from a message to the list. The reader's Back button returns.
- In full screen, the keyboard focus is not held inside the compose window.
- An Older mail click in Sent made while the list's first page reloads does nothing; click it again.
- A delete or move made in one browser shows in another member's list on its next refresh, within 20 seconds.
- Mail deleted for good, by Delete forever, Empty Trash or Empty Spam or after 30 days, leaves the listing and the search at once, but its bytes can stay in the mailbox file until SQLite reuses the space. A member who downloads the file can recover it with SQLite tools. A purge removes the whole file.
