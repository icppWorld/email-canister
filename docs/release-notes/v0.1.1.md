# v0.1.1

## Overview

A webmail fix release. Plain mail now shows in the brand's colours, and the sender warning, which showed on most mail sent through a mail service, is replaced by a neutral note naming the domain that delivered the message. The backend is unchanged.

## Highlights

- Plain mail, as the composer and common mail programs write it, is shown on the brand's raised surface in its ink colour, font and light or dark theme, with links in the brand's action colour. Mail that brings its own colours, images, tables or boxed borders keeps the white page it was designed for, so it stays readable in the dark theme.
- The reader shows "via example.com" when the envelope sender's domain is not exactly the `From` domain, and "via an unnamed domain" when the envelope sender is empty. Domains are compared as written, without converting between Unicode and punycode, so a Unicode `From` domain shows a note when the envelope gives a punycode name. The red "sender could not be confirmed" warning is gone: the SMTP gateway passes no SPF, DKIM or DMARC result, so a differing domain was no evidence of forgery.
- `brand.mjs` checks the contrast of `ink` and `action` on `surface-raised`, and accepts only safe values for roles and font families.

## Candid API changes

None.

## Upgrade notes

The backend wasm is the same as in v0.1.0, sha256 `16d977d82dcc40490667993468ff8aabb5d3cbb99d61fffa462d0cf84b64ebdf`, so the backend canister needs no upgrade. Update the deployment's release pins to this release, run `webmail/brand.mjs` on this release's `webmail/dist` with the deployment's brand and settings, and deploy its output to the webmail canister.

`brand.mjs` is stricter about role values and font families (see below). Run it before the deploy: a brand it refuses names the role or family to fix.

The relay bridge is unchanged.

## Webmail and settings changes

- The Sent view shows a sent message the way the reader does: plain mail on the brand's page, and inline `data:` images allowed in its frame, as in the inbox. Remote content stays blocked.
- Role values must now be colours, lengths or shadows: letters, digits, `#%.,()/*_+-` and whitespace, with round brackets closed and no CSS comment.
- Font families must be a comma-separated list of names, in quotes or bare. A bare name is made of CSS identifiers, so a name with a digit-led or dotted word must be quoted, such as `"Source Sans 3"`.
- A brand that used other values stops with a `role` or `font family` error. Such values could break the style sheet before.
- `brand.mjs` now also warns when `ink` or `action` falls below 4.5:1 on `surface-raised`.

## Known issues

- When the mail gateway rate-limits a send with HTTP 429, the relay bridge marks the message rejected instead of retrying it. Sending it again from the webmail works, because a resend is a new attempt. Some messages that were never sent are reported as outcome unknown. Both are fixed in v0.1.3.
- The sender is not verified, and the red sender warning of v0.1.0 is gone. A forged `From` sent from another domain shows only that domain as "via", as genuine mail sent through a mail service does, and a forged `From` on the envelope sender's own domain shows nothing when that domain has no strict SPF record. Tell users to check the "via" domain on unexpected requests. DKIM verification in the canister, planned for v0.2.0, brings back a warning for mail no aligned signature covers.
- Replies may not thread in the recipient's mail program, because the mail gateway sets its own `Message-ID`.
- Messages over about 2 MB are refused by the SMTP gateway.
