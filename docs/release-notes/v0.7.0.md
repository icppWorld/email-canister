# v0.7.0

## Overview

A webmail release. Every action button is an icon with a tooltip, so the list's toolbar fits on one line. The divider between the message list and the reader can be dragged. Sent gets checkboxes, a hover Delete, a bulk Delete and Empty Sent, through one new backend method, `mail_outbox_delete_many`. Attach adds files, and the compose window lists them. No data changes: the backend is upgraded in place. The relay bridge is unchanged.

## Highlights

For members, in the webmail:

- **Every action button is an icon with a tooltip.** The list's toolbar, the reader's toolbars, Empty Trash, Empty Spam and Empty Sent, Older mail, Compose and the compose window, Sign in and Sign out, the Admin panel, Blocked senders and the notes. A button's tooltip and its name for screen readers are its old label. Items in a ⋮ menu keep their text, with an icon in front. The folder and mailbox buttons beside the mail and the reader's attachment buttons keep their text too. With messages ticked, the list's toolbar now fits on one line.
- **A draggable divider** between the message list and the reader. Drag it, or focus it and use the arrow keys, Home and End; a double-click returns it to its first width. The list keeps at least 260px and the reader at least 320px. The width is kept in this browser, and applies in every folder. At phone width there is no divider: the list and the message take turns, as before.
- **Sent: checkboxes, a hover Delete, a bulk Delete and Empty Sent.** Sent mail is deleted for good, after a confirmation, and its room in the mailbox is freed at once.
  - Mail being sent cannot be ticked or deleted, and Empty Sent keeps it.
  - Deleting mail still waiting to be sent cancels it. The confirmation says so.
  - The note says how many messages were deleted, and how many could not be.
- **Attach adds files.** Each pick adds to the attachments, where it used to replace them. A file picked again, with the same name and size as one attached, replaces it, so a file edited to the same size is sent as it is now. A file whose size changed is added beside the earlier copy, which its Remove button takes off. The compose window lists the files, each with a Remove button.
- **Only listed mail stays ticked.** A message a search or a reload takes off the list, or that starts sending, loses its tick, so it never comes back ticked into a later action.

For admins, in the backend:

- **`mail_outbox_delete_many`** deletes up to 200 messages of the outbox in one write, frees their room, and replies with the ids it deleted. As `mail_outbox_delete`, it deletes a message in any state but being sent, so it cancels mail still waiting to be sent; for mail that was never tried, it frees the send's `client_id`, so a later send with that `client_id` sends a new message. It skips mail being sent, and mail no longer there. Members may call it, as `mail_outbox_delete`.

For maintainers:

- **Tests:** native and replica tests for `mail_outbox_delete_many`, and browser tests for every change and every review fix. The release upgrade test still starts from v0.5.0: v0.7.0 adds no schema step, so it runs the same steps as an upgrade to v0.6.0.

## Candid API changes

- New: `mail_outbox_delete_many : (text, vec nat64) -> (vec nat64)`. At most 200 ids, or it traps with "too many messages at once".

A client built for v0.6.0 keeps working.

## Upgrade notes

**The backend is upgraded in place, and keeps its mail.** No data changes: `control.db` stays at version 2 and the mailbox files at version 4. Upgrade the backend first, then deploy the webmail: the v0.7.0 webmail needs `mail_outbox_delete_many` for deletion in Sent, while the v0.6.0 webmail works on the v0.7.0 backend. Users reload any webmail tab left open from before the deploy. The relay bridge is unchanged: nothing to copy into the bridge's app.

This holds for a backend running v0.6.0. A backend on an earlier release first upgrades to v0.6.0 as its upgrade notes say.

1. Stop the backend and take a snapshot (`icp canister snapshot create email-canister --environment ic`).
2. Pin v0.7.0 in the deployment repository, whose `icp.yaml` installs the release's wasm only when its sha256 matches. Upgrade the backend (`icp canister install email-canister --mode upgrade --environment ic`), and start it. The wasm sha256 is `6d354676e76f0adc976072bc5c244c04c86f8d544afcc7ab941f57169fe7ab4b`.
3. Deploy the webmail, rebuilt with the deployment's brand. The release's unbranded `dist` hash is `4c3bb5de8f4dc4da0648d00185c00de7f3dbaf33637bcc79facea1cf78abc43f`; the branded output differs from it. The brand format and `brand.mjs` options are unchanged.
4. Run the deployment's checks. `admin_check` on each mailbox should answer `ok`. A file over about 2.6 GB does not fit in one whole-file check: check it table by table (`admin_check("<local>", opt "<table>")`).
5. Once the upgrade is confirmed, and at the latest 7 days after it, delete the snapshot (`icp canister snapshot delete email-canister <id> --environment ic`).

**Rolling back:** v0.6.0 reads the same data, so no snapshot is needed for it. Pin v0.6.0 again in the deployment repository, deploy the v0.6.0 webmail first (it works on the v0.7.0 backend, while the v0.7.0 webmail needs `mail_outbox_delete_many`), then stop the backend, install the v0.6.0 wasm with `--mode upgrade`, and start it. Mail received and changes made since the upgrade stay; outbox mail deleted since stays deleted. Restoring the snapshot instead undoes everything since the upgrade, as the v0.6.0 notes describe.

## Webmail and settings changes

- Every action button is an icon with a tooltip, as above. The accessible names are the old labels, so scripts that find buttons by role and exact name keep working; scripts that find them by visible text do not. As the old labels are now names and tooltips, a lookup by label or title that is not exact can also match a button: a label `Domain` now also matches the Admin panel's `Save domain`, and a member's principal also matches the title of their `Remove` button. Make such lookups exact.
- The divider's width is stored in the browser's `localStorage` under `list-width`.
- Sent's checkboxes, hover Delete, bulk Delete and Empty Sent, and Attach, as above.
- The `brand.mjs` options and the brand format are unchanged.

## Known issues

- A send from a full mailbox does not free its expired mail: the send is refused, and the refusal marks nothing. Empty Trash or Empty Spam frees room at once, and the next mail that arrives, or a move of mail, starts the cleanup.
- No timer cleans expired mail by itself: a mailbox is cleaned after a delivery, a move or a 452. In a mailbox that nobody mails and nobody uses, expired mail stays listed, and can still be restored.
- At 1,000 blocked addresses, a new block replaces the oldest without saying so: mail from the oldest address reaches the Inbox again.
- The reader's ⋮ Block sender can be offered for an envelope sender that the canister refuses as an address. The block then fails, with a message that says why.
- Undo of a Spam lifts a block it made also when another member, or a second Spam click, blocked the same address right after it, as their block found the address blocked already.
- Spam blocks the `From` address the message claims, which nothing verifies. Spam that forges a real sender's address blocks that sender, whose genuine mail then goes to Spam until the address is unblocked. Only the mailbox's own domain and its subdomains are spared.
- Spam only moves the mail, and its note does not say that no block was made, when the list has no `From` address for it: mail parsed after the list was loaded (until the list's next refresh, within 20 seconds), quarantined mail, and a `From` address `mail_block` refuses.
- Not spam does not lift a block of the envelope sender, which also files mail in Spam; the next such mail goes to Spam again. Unblock the envelope sender on the Blocked senders page.
- A block or unblock whose reply is lost after the canister made it shows as failed in the note, and Undo does not take it back. The Blocked senders page shows whether the address is blocked.
- Undo of a Not spam blocks the address again in the name of the member who clicked Undo, at that time.
- Spam blocks the sender of a message that another member moved or deleted meanwhile, which the note reports as no longer here; Not spam unblocks it the same way.
- Mark unread in the list's toolbar or a row's hover action, on the message that is open, can race the reader's own mark as read, so the message can end up read. The reader's ⋮ Mark unread waits for it.
- At phone width, the device's back gesture leaves the webmail rather than returning from a message to the list. The reader's Back button returns.
- In full screen, the keyboard focus is not held inside the compose window.
- An Older mail click in Sent made while the list's first page reloads does nothing; click it again.
- A delete or move made in one browser shows in another member's list on its next refresh, within 20 seconds.
- Mail deleted for good, by Delete forever, Empty Trash or Empty Spam or after 30 days, leaves the listing and the search at once, but its bytes can stay in the mailbox file until SQLite reuses the space. A member who downloads the file can recover it with SQLite tools. A purge removes the whole file.
- Sent's note says how many messages could not be deleted, and that they were being sent or deleted already, but not which of the two applies to which message.
- Compose tells files apart by name and size, as the browser gives no path: of two different files with the same name and size, the later one picked replaces the earlier.
- The width of the message list is kept per browser. An arrow key or double-click on the divider in a narrow window stores the narrower width, which then applies in a wide window too.
- The divider's limit is measured when the window resizes. When the pointer changes from mouse to touch without a resize, the divider widens and the reader can be left up to 9px under its 320px until the next resize.
- A long Empty Sent's note shows over the mailbox open when it finishes, also when a member switched to another mailbox meanwhile. It holds only counts.
