# v0.1.0

## Overview

The first release: email for one domain from canisters you control, packaged so a deployment needs no compiler. The backend wasm is built reproducibly, the webmail is built once and configured per deployment, and the relay bridge for the sending side is included as a template.

## Highlights

- Receiving through the DFINITY SMTP gateway, with deduplication, quarantine of unreadable mail, and decoding of the common charsets.
- Storage and full-text search in SQLite on stable memory.
- Sending through the relay bridge, with an idempotent outbox: a retried call never sends twice, and a lost outcome is shown as unknown instead of being resent.
- Webmail with Internet Identity sign-in, sandboxed HTML, an Admin screen for controllers, and a return to the sign-in page when a sign-in ends.
- `webmail/brand.mjs` configures the webmail for a deployment: backend canister, sign-in origin, and an optional brand with logo, icons, fonts and colours.
- `scripts/configure.sh` sets the domain and bridge; `scripts/check.sh` checks a live deployment.

## Upgrade notes

For a backend deployed from an earlier unreleased build of the same code: stop the canister, install this wasm with mode upgrade, and start it. The data is kept; timers are re-armed on upgrade.

## Webmail and settings changes

The webmail no longer has build-time settings. Run `webmail/brand.mjs` on `webmail/dist`, then deploy its output.

## Known issues

- Replies may not thread in the recipient's mail program, because the mail gateway sets its own `Message-ID`.
- Messages over about 2 MB are refused by the SMTP gateway.
