# v0.9.0

## Overview

A webmail release that follows an audit of the reader: what a message, its sender or another site can learn about the person reading. Links in a message now work, opening in a new tab. A message goes through an allow-list of HTML before it is shown, so that markup no rule knows of is left out by default. Several ways an opened message, or a site that opens the webmail, could learn something about the reader are closed. The backend and the relay bridge are unchanged.

## Highlights

For members, in the webmail:

- **Links in a message work.** A click opens the link in a new tab. Before, it replaced the message with the browser's "This content is blocked" page, and a link that asked for a new tab did nothing.
  - Only a link with a full `http` or `https` address opens. Any other keeps its text but loses its address, so a click on it does nothing: a `mailto:` or another scheme, a script, an address relative to the webmail's own.
  - The page that opens gets no referrer and no handle on the webmail.
  - A link's `ping` and `xlink:href` are removed: with `ping`, a click would report itself to a server of the sender's choosing.
- **A message is cleaned with an allow-list.** Only the HTML elements and attributes a maintained list (DOMPurify) allows reach the reader. Before, the webmail removed a list of its own of elements known to leak, which a new element in some browser would have passed.
  - Text in an element the list drops is kept, with a few exceptions such as a `noscript`.
  - Style sheets, colours and inline images stay as the message wrote them.
- **Drawings and formulas, SVG and MathML, are shown as their text alone.** They bring links and animations of their own kinds, which could give a link another address after it was checked. The large mail services do not draw them either.
- **Less for a sender to learn when a message is opened:**
  - One browser looked up the host of every link in an opened message. The reader now switches that off.
  - One browser loads a `model` element outside the content security policy. It is left out.
- **Less for a sender to learn after Show images:** in the browsers that support it, an image request no longer carries the reader's cookies for the image's host, with which the host could recognise the reader.
- **Another site cannot watch the webmail.** A site that opened the webmail in a new tab kept a handle on it: it could tell when an HTML message was on screen, and probe which mailboxes the reader belongs to. The webmail is now served with a policy that cuts that handle.
- **Reversed names are shown as they are.** Control characters and the marks that reverse, embed or isolate text are shown as a replacement character, `�`, in the names, addresses, subjects, previews and attachment names the webmail shows: in the list, the reader and its "via" line, a reply's To, the notes, Blocked senders and Sent. With such a mark, a file named `invoice`, the mark and `fdp.exe` displayed as `invoiceexe.pdf`; it now shows as `invoice�fdp.exe`. Two addresses that differ only by a mark never look alike, so a note or Blocked senders cannot name one address for another.

For maintainers:

- **Tests:** browser tests for each change and each review fix, among them a page on another origin that opens the webmail, a link that opens a tab, and a message built to get markup past the list.
- **A new dependency in the webmail:** DOMPurify 3.4.18, under Apache-2.0. See `THIRD_PARTY.md`.

None.

## Upgrade notes

**Only the webmail changes.** Deploy the v0.9.0 webmail; do not redeploy the backend or the bridge. The backend wasm is the same as v0.7.0's and v0.8.0's, sha256 `6d354676e76f0adc976072bc5c244c04c86f8d544afcc7ab941f57169fe7ab4b`, so a deployment repository's `icp.yaml` keeps its hash. This holds for a deployment whose backend runs v0.7.0 or v0.8.0. One on an earlier release first upgrades its backend as v0.7.0's upgrade notes say.

A deployment that changed `webmail/public/.ic-assets.json5` takes over this release's two changes to it, named under "Webmail and settings changes".

1. Pin v0.9.0 in the deployment repository.
2. Deploy the webmail, rebuilt with the deployment's brand. The release's unbranded `dist` hash is `826edfea86138cefeeeceb0cf098476b385517a6fcf9295969bea745244bf338`; the branded output differs from it. The brand format and `brand.mjs` options are unchanged.
3. Run the deployment's checks.
4. Reload the webmail and sign in to it once. The new opener policy touches the sign-in window, and the browser tests cover it only against the local Internet Identity. A deployment that comes from the v0.7.0 webmail can show the earlier webmail once more, as that was served without `Cache-Control`: close the tab and open the webmail again first.
5. Optional, for a deployment whose controller's identity is also a member of a mailbox: add a second identity as the member that reads the mail, and remove the controller's from the mailboxes, in the Admin screen. `docs/setup-guide.md` says why.

**Rolling back:** pin the release the deployment ran before in the deployment repository, and deploy its webmail. No data changes either way.

## Webmail and settings changes

- In `webmail/public/.ic-assets.json5`: the page is served with `Cross-Origin-Opener-Policy: same-origin-allow-popups`, and its content security policy names `frame-src 'none'`, which `default-src 'none'` implied before.
- The message frame's sandbox changes from `""` to `allow-popups allow-popups-to-escape-sandbox`, for links. It still allows no script, no form, no same-origin access and no move of the webmail's own tab. The frame is also `credentialless`.
- The frame's document switches off looking up hosts ahead (`x-dns-prefetch-control`).
- `docs/setup-guide.md` advises a controller identity that is a member of no mailbox.
- The `brand.mjs` options and the brand format are unchanged.

## Known issues

- A link to a file that the browser would download can open an empty tab and save nothing: the message frame's sandbox does not allow downloads.
- A `mailto:` link in a message does nothing. Copy the address, or use Reply.
- A link to a place in the message itself, as in a table of contents, does nothing. Before this release a click on one replaced the message with the browser's blocked page.
- A message's own frames are not shown.
- A message whose cleaned markup still holds something the reader refuses when it is read again, and every HTML message in a browser the allow-list cannot work in, is shown as its text alone.
- A press on a link lets some browsers connect to its host a moment before the click completes.
- After Show images, what a message loads can depend on the reader: its style sheets can pick an image by the window's width, a light or dark theme, a link under the pointer or a printout, and so tell the sender those. An image's server can also name other hosts for the browser to connect to.
- The image requests carry no cookies only in browsers that know the `credentialless` attribute. The others leave such cookies out, or keep them apart per site, by their own settings.
- A drawing or a formula in a message, SVG or MathML, is shown as its text.
- A message's own text keeps its marks that reverse text: the replacement character is used for names, addresses, subjects and file names, not for what a message says.
- A reply to an address with such a mark goes to the address as shown, with the replacement character, which reaches no one.
- An `id` or a `name` in a message that is also the name of something a web page or a form has of its own, such as `title` or `body`, is dropped, so a style sheet's rule for that id does not apply. A `noscript`'s content is not shown.
- A message is read twice and written out once when it opens. With very large inline images that takes a noticeable moment.
- Show images is not offered for some rare forms of remote image, which then stay blocked: a remote image that is not the first candidate of a CSS `image-set()`, and an image whose address is written with CSS escapes in a `<style>` element.
- Show images can be offered where it then shows nothing: a `<style>` element whose only remote address is a style sheet it imports or a font, which stay blocked, and an image at an `http:` address that has no https version.
- Images shown stay shown while the message stays open. A click on the open message's row in the list does not block them again; opening another message and returning does.
- A message built to repeat a large inline image many times can freeze the reader's tab when it is opened. Reload the webmail and delete the message from the list without opening it.
- A send from a full mailbox does not free its expired mail: the send is refused, and the refusal marks nothing. Empty Trash or Empty Spam frees room at once, and the next mail that arrives, or a move of mail, starts the cleanup.
- No timer cleans expired mail by itself: a mailbox is cleaned after a delivery, a move or a 452. In a mailbox that nobody mails and nobody uses, expired mail stays listed, and can still be restored.
- At 1,000 blocked addresses, a new block replaces the oldest without saying so: mail from the oldest address reaches the Inbox again.
- The reader's ⋮ Block sender can be offered for an envelope sender that the canister refuses as an address. The block then fails, with a message that says why.
- Undo of a Spam lifts a block it made also when another member, or a second Spam click, blocked the same address right after it, as their block found the address blocked already.
- Spam blocks the `From` address the message claims, which nothing verifies. Spam that forges a real sender's address blocks that sender, whose genuine mail then goes to Spam until the address is unblocked. Only the mailbox's own domain and its subdomains are spared.
- Spam only moves the mail, and its note does not say that no block was made, when the list has no `From` address for it: mail parsed after the list was loaded (until the list's next refresh, within 20 seconds), quarantined mail, and a `From` address `mail_block` refuses.
- Not spam does not lift a block of the envelope sender, which also files mail in Spam; the next such mail goes to Spam again. Unblock the envelope sender on the Blocked senders page.
- A block or unblock whose reply is lost after the canister made it shows as failed in the note, and Undo does not take it back. The Blocked senders page shows whether the address is blocked.
- Undo of a Not spam blocks the address again in the name of the member who clicked Undo, at that time.
- Spam blocks the sender of a message that another member moved or deleted meanwhile, which the note reports as no longer here; Not spam unblocks it the same way.
- Mark unread in the list's toolbar or a row's hover action, on the message that is open, can race the reader's own mark as read, so the message can end up read. The reader's ⋮ Mark unread waits for it.
- At phone width, the device's back gesture leaves the webmail rather than returning from a message to the list. The reader's Back button returns.
- In full screen, the keyboard focus is not held inside the compose window.
- An Older mail click in Sent made while the list's first page reloads does nothing; click it again.
- A delete or move made in one browser shows in another member's list on its next refresh, within 20 seconds.
- Mail deleted for good, by Delete forever, Empty Trash or Empty Spam or after 30 days, leaves the listing and the search at once, but its bytes can stay in the mailbox file until SQLite reuses the space. A member who downloads the file can recover it with SQLite tools. A purge removes the whole file.
- Sent's note says how many messages could not be deleted, and that they were being sent or deleted already, but not which of the two applies to which message.
- Compose tells files apart by name and size, as the browser gives no path: of two different files with the same name and size, the later one picked replaces the earlier.
- The width of the message list is kept per browser. An arrow key or double-click on the divider in a narrow window stores the narrower width, which then applies in a wide window too.
- The divider's limit is measured when the window resizes. When the pointer changes from mouse to touch without a resize, the divider widens and the reader can be left up to 9px under its 320px until the next resize.
- A long Empty Sent's note shows over the mailbox open when it finishes, also when a member switched to another mailbox meanwhile. It holds only counts.
