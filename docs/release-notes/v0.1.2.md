# v0.1.2

## Overview

Mail for a domain registered outside Caffeine. Caffeine connects such a domain only as `www`, so nothing served the bare domain, where the SMTP gateway looks for the backend. This release adds a domain canister that a deployment owns and puts on the bare domain. It also includes the webmail fixes of v0.1.1, which was not published on its own. The backend is unchanged.

## Highlights

- `domain/domain.mjs` writes a small asset canister for the bare domain. It serves `/.well-known/ic-smtp-canister-id` for the SMTP gateway and `/.well-known/ic-domains` for the IC's custom-domain service, and sends browsers on every other path to `https://www.<domain>`, keeping the path, query and fragment. It works without JavaScript too, then to the website's home page.
- The setup guide has a new step 6, "Serve the bare domain": when it is needed, the canister, the DNS records and the registration with the custom-domain service.
- `scripts/check.sh` also checks that the domain is registered with the IC's custom-domain service, and with `--www` that `https://www.<domain>/` answers.
- The webmail fixes of v0.1.1: plain mail in the brand's colours, and the delivering domain shown as "via" instead of a sender warning. See `v0.1.1.md`.

## Upgrade notes

The backend wasm is the same as in v0.1.0 and v0.1.1, sha256 `16d977d82dcc40490667993468ff8aabb5d3cbb99d61fffa462d0cf84b64ebdf`, so the backend canister needs no upgrade. The relay bridge is unchanged.

Update the deployment's release pins to this release. From v0.1.0, also redeploy the webmail, as `v0.1.1.md` describes: run `webmail/brand.mjs` first, because it is stricter about role values and font families.

For a domain registered elsewhere, follow the setup guide's step 6: declare and create the domain canister, write it with `domain/domain.mjs`, deploy it, set the bare domain's DNS records and register the domain. Set the MX records only after `scripts/check.sh` shows the bare domain handing mail to the backend. A domain bought through Caffeine needs none of this.

## Known issues

- When the mail gateway rate-limits a send with HTTP 429, the relay bridge marks the message rejected instead of retrying it; sending it again from the webmail works. Some messages that were never sent are reported as outcome unknown. Both are fixed in v0.1.3.
- The sender is not verified, and the red sender warning of v0.1.0 is gone; see `v0.1.1.md`. DKIM verification in the canister is planned for v0.2.0.
- A domain canister on plain A and AAAA records depends on `icp1.io`'s addresses of today. Use ALIAS or ANAME records where the registrar offers them.
- Replies may not thread in the recipient's mail program, because the mail gateway sets its own `Message-ID`.
- Messages over about 2 MB are refused by the SMTP gateway.
